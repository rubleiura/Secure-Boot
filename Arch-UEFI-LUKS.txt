# 🎨 v4.1 — ЕДИНОЕ ОФОРМЛЕНИЕ ПРОВЕРОК в конце каждого блока:
#    • clear — старый вывод не мешает;
#    • перед каждым тестом — «всплывающее окно»: цветная рамка с заголовком,
#      что проверяется и каким должен быть результат;
#    • между тестами — пустая строка, чтобы результаты не сливались;
#    • в самом конце — зелёная рамка: ЧТО СДЕЛАНО в блоке и КУДА ИДТИ ДАЛЬШЕ
#      (чтобы не забыть, какая операция только что выполнена).
#    ❗ Настоящие dialog-окна намеренно НЕ используются: dialog читает клавиши
#    из stdin и «съедает» хвост вставленного блока (та же беда, что была с
#    mkfs в БЛОКЕ 7). Окна здесь рисуются мгновенно через echo — вставку не
#    ломают, ничего нажимать не нужно. Внутри рамок нет эмодзи — только
#    символы фиксированной ширины, поэтому рамки ровные на любом терминале.
# 🏔️ Логотип Arch Linux — ASCII-арт в этой шапке и цветной приветственный
#    баннер при запуске БЛОКА 0 (печатается сразу после clear).
# 🔤 v4.2 — возвращены ПЕРЕМЕННЫЕ-ЗАГЛУШКИ исходного макета (групповая
#    замена в текстовом редакторе): «sdx» — целый диск (БЛОК 4/5),
#    «sda1/sda2» — разделы (БЛОК 6 и далее), «defaults» — опции монтирования
#    (БЛОК 7C), «Russia» — зеркала (БЛОК 0/1/2/9). Токен «sdx» не пересекается
#    с «sda1/sda2» — порядок групповой замены не важен:
#    sdx→nvme1n1, sda1→nvme1n1p1, sda2→nvme1n1p2.
# 🔐 luks-v1.2 — ШИФРОВАННАЯ редакция на базе v4.4. Токены те же, добавился
#    «cryptroot» (имя LUKS-контейнера — можно не менять). Строка
#    /dev/mapper/cryptroot токеном НЕ является: она одинакова на любом диске.
#    LUKS-пароль токеном тоже НЕ является — его вводят вручную в интерактивной
#    команде (БЛОКИ 7 и 7A), в файле он нигде не хранится.
# 🎨 v4.3 — текст в заголовках окон снова чёрный БЕЗ bold: TB/TG/TY теперь
#    \e[22;30;46m / \e[22;30;42m / \e[22;30;43m вместо \e[1;30;…m]. Причина: «bold black»
#    по соглашению терминалов рисруется как «яркий чёрный» (серый), и в Konsole
#    (палитра Breeze) он сливался с заливкой заголовка (скриншот владельца
#    от 2026-10-08). Простой чёрный на цветной заливке контрастен везде.
#    ВАЖНО: bold приходил не только от собственного кода 1 у плашки, но и
#    наследовался от рамки (${CB} в начале строки echo), поэтому к плашке
#    добавлен SGR 22 (normal intensity) — он гасит чужой bold.
# 🎨 v4.4 — текст заголовков окон: ЖИРНЫЙ + truecolor-чёрный (SGR 38;2;0;0;0).
#    Проверка владельца (Konsole, скриншот от 2026-10-08): v4.3 не помог —
#    Konsole не сняла кодом 22 bold, унаследованный от рамки, и «чёрный» снова
#    нарисовался «ярким чёрным» (серый #7F8C8D на заливке, контраст 1.46:1 —
#    пиксель-анализ обоих скриншотов: ядро глифов везде #7F8C8D).
#    v4.4 задаёт цвет truecolor-ом: терминал рисует ровно #000000 — это НЕ
#    зависит ни от палитры, ни от маппинга «bold→яркий». Bold вернули ОСОЗНАННО:
#    все остальные элементы рамок жирные, тонкий чёрный текст глаз тоже читал
#    как «тусклый». Контраст чисто-чёрного на заливках: циан 8.7:1, зелёный
#    10.2:1, жёлтый ~12:1 (WCAG AAA). Плитки теперь:
#    \e[1;30;38;2;0;0;0;46m / \e[1;30;38;2;0;0;0;42m / \e[1;30;38;2;0;0;0;43m;
#    30 перед 38;2 — запасной вариант для терминалов без truecolor (Konsole,
#    GNOME Terminal, kitty, alacritty — все с truecolor).
#
# ✅ База v4.2 подтверждена реальным прогоном (VirtualBox + SSH); v4.3 и v4.4
#    отличаются от неё только цветами заголовков окон (🎨 v4.3 и 🎨 v4.4 — правки
#    по скриншотам владельца из Konsole: «bold black» сливался с заливкой, SGR 22
#    не снял унаследованный bold — в v4.4 цвет задан truecolor-ом + bold).
#    Secure Boot
#    активируется сам после записи ключей, UKI грузится, снимки btrfs появляются
#    в меню мгновенно (path-юнит), plymouth (тема bgrt) работает.
# ⏳ Шифрованная редакция luks-v1.2 проверена прогоном всех блоков в песочнице
#    (tools/run_block.py) и контролем рамок (tools/check_frames.py). Прогон в
#    VirtualBox с включённым Secure Boot — отдельный шаг владельца.
#
# Ключевые решения. Сначала — шифрование (отличие этой редакции), затем —
# общие решения, унаследованные от незашифрованного эталона v4.4:
# 🔐 ШИФРОВАНИЕ (главное отличие этой редакции от незашифрованной v4.4):
# • Корень — Btrfs ВНУТРИ LUKS2-контейнера cryptroot на разделе sda2.
#   LVM НЕ используется: структура ровно как в эталоне v4.4, между разделом и
#   Btrfs добавлен один слой dm-crypt (меньше слоёв — меньше точек отказа).
# • Swap-раздела нет (zram из БЛОКА 13), значит гибернация не настраивается —
#   как и в эталоне. Шифруется только корень: ESP остаётся открытым (это норма:
#   на нём загрузчик, ядро и UKI — всё подписано и проверяется прошивкой).
# • LUKS2 + argon2id (значения cryptsetup по умолчанию), открытие ТОЛЬКО по
#   паролю: ни key-файла на ESP, ни TPM2. ЗАБЫЛИ ПАРОЛЬ — ДАННЫЕ ПОТЕРЯНЫ.
# • Контейнер открывает initramfs (хук sd-encrypt) по параметру ядра
#   rd.luks.name=<UUID контейнера>=cryptroot. Параметр встроен в подписанный
#   UKI → при включённом Secure Boot подменить параметры шифрования нельзя.
# • discard разрешён (rd.luks.options=discard в cmdline + discard=async у Btrfs
#   на SSD): TRIM работает, ценой раскрытия сведений о занятом месте на диске.
# • Интерактивные команды LUKS (luksFormat, open) ВСЕГДА последние в своём
#   блоке: cryptsetup читает пароль из stdin и «съел» бы хвост вставки — та же
#   причина, по которой в макете нет dialog. Из-за этого БЛОК 7 развернулся
#   в цепочку 7 → 7A → 7B → 7C (форматирование → открытие → Btrfs → монтаж).
# • Раскладка консоли — us: в live-среде loadkeys us перед вводом пароля,
#   в установленной системе KEYMAP=us при шрифте cyr-sun16 (БЛОК 9). Иначе
#   пароль, заданный кириллицей, не ввести с флешки восстановления.
# • Снимки btrfs в меню загрузки РАБОТАЮТ и при Secure Boot (БЛОК 13A):
#   записи-снимков — Type #1 (ядро + initramfs + свои options), а ограничение
#   SB касается только встроенной .cmdline у UKI. В options попадает полная
#   строка параметров, включая rd.luks.name=…, поэтому initramfs открывает
#   контейнер и монтирует снимок как корень (пароль спрашивается так же).
#
# • Загрузчик — systemd-boot + UKI (НЕ GRUB: при включённом Secure Boot GRUB из
#   Arch без shim падает в grub rescue). Ядро — linux-lts, параметры ядра —
#   в /etc/kernel/cmdline.
# • Secure Boot — sbctl: свои ключи + подпись systemd-boot (ОБА экземпляра),
#   UKI, ядра и memtest (БЛОК 17).
# • Корень монтируется ЯВНО по ИМЕНИ: subvol=/@ в fstab (БЛОК 9) и
#   rootflags=subvol=@ в параметрах ядра (БЛОК 12). Подтом по умолчанию НЕ
#   меняется: иначе «Восстановить копию» в btrfs-assistant (переименование
#   подтомов) оставит систему загруженной из backup-копии.
# • Снимки btrfs в меню — БЛОК 13A (замена grub-btrfs); если после отката дерево
#   снимков осталось в @_backup_* — БЛОК 13B вернёт его в корень.
# • Права на ESP: fmask=0177,dmask=0077 (БЛОК 9) — иначе systemd-boot пишет про
#   world-accessible random seed. Побочно: /boot читается только через sudo.
# • quiet splash loglevel=3 — ТОЛЬКО в БЛОКЕ 20, после первой успешной загрузки,
#   иначе причину сбоя не увидеть.
# ℹ️ Нумерация блоков оставлена как в v3. БЛОК 19 (аварийное восстановление),
#    удалённый в незашифрованной редакции, ЗДЕСЬ ВЕРНУЛСЯ: с LUKS он необходим
#    (загрузка с флешки → cryptsetup open → arch-chroot). При обычной установке
#    он ПРОПУСКАЕТСЯ: после БЛОКА 18 переходите сразу к БЛОКУ 20.
#    Внутри БЛОКА 7 появились 7A/7B/7C — см. «Ключевые решения» выше.

# 💡 Печатается сразу после clear — начало работы с макетом видно издалека.
#    Цвет — «фирменный» cyan Arch (как рисует neofetch): задаётся одним printf

#    нужно. Heredoc << 'EOF' закавычен: обратные кавычки внутри логотипа —
#    обычные символы, команды не выполняются. Ничего не читает stdin — вставку
#    блока не ломает.

LW=$'\e[1;37m'   # яркий белый — заголовок

                                       .o+`
                                      `ooo/

                        `/ossssso+/:-        -:/+osssso+-
                       `+sso+:-`                 `.-/+oso:
                      `++:.                           `-/+/
                      .`                                 `/
EOF
printf '%s\n' "${LW}              A R C H   L I N U X   ·   Б Л О Ч Н Ы Й   М А К Е Т${CN}"
printf '%s\n' "${LA}      Btrfs · LUKS2 · systemd-boot + UKI · Secure Boot · редакция luks-v1.2${CN}"
echo

def haversine(lat1, lon1, lat2, lon2):
    R = 6371.0
    dlat = math.radians(lat2 - lat1)
    dlon = math.radians(lon2 - lon1)
    a = math.sin(dlat/2)**2 + math.cos(math.radians(lat1)) * math.cos(math.radians(lat2)) * math.sin(dlon/2)**2
    return R * 2 * math.atan2(math.sqrt(a), math.sqrt(1-a))

def get_ip_location():
    apis = [
        ("https://ipapi.co/json/", "ipapi.co"),
        ("https://ipinfo.io/json", "ipinfo.io"),
    ]
    for api_url, api_name in apis:
        try:
            print(f"  🔄 Пробуем {api_name}...")
            with urllib.request.urlopen(api_url, timeout=5) as resp:
                data = json.loads(resp.read().decode())

                if api_name == "ipapi.co":
                    if "error" in data:
                        continue
                    if "latitude" not in data or "longitude" not in data:
                        continue
                    lat = float(data.get("latitude", 0))
                    lon = float(data.get("longitude", 0))
                    country = data.get("country_name", "Unknown")

                elif api_name == "ipinfo.io":
                    if "bogon" in data:
                        continue
                    if "loc" not in data:
                        continue
                    loc = data.get("loc", "0,0").split(",")
                    lat = float(loc[0])
                    lon = float(loc[1])
                    country = data.get("country", "Unknown")
                else:
                    continue

                if lat != 0 and lon != 0:
                    print(f"  ✅ Использован API: {api_name}")
                    return lat, lon, country

        except Exception as e:
            print(f"  ⚠️ {api_name} недоступен: {e}")
            continue

    print("❌ Все API недоступны. Проверьте подключение к интернету.")
    sys.exit(1)

def main():
    print("🌐 Определение местоположения по IP...")
    my_lat, my_lon, my_country = get_ip_location()
    print(f"✅ Вы находитесь: {my_country} ({my_lat:.4f}, {my_lon:.4f})\n")

    distances = []
    for country, (cap_lat, cap_lon) in CAPITALS.items():
        if country == my_country:
            continue
        dist = haversine(my_lat, my_lon, cap_lat, cap_lon)
        distances.append((country, dist))

    distances.sort(key=lambda x: x[1])

    print(f'{"#":<3} {"Страна":<25} {"Расстояние (км)":<10}')
    print("-" * 45)
    for i, (country, dist) in enumerate(distances[:10], 1):
        print(f"{i:<3} {country:<25} {dist:.0f}")
    print("-" * 45)
    print("✅ Готово! Используйте список выше для настройки.")

if __name__ == "__main__":
    main()

# 📌 Схема разделов:
# • sda1 — ESP (EFI System Partition), 1024 МБ, тип ef00.
# • sda2 — LUKS2-контейнер cryptroot (внутри — Btrfs), всё оставшееся место,
#   тип 8309 (Linux LUKS). Swap нет — используется zram из БЛОКА 13.

# 🧹 Очистка экрана терминала
clear

# ШАГ 1: ОЧИСТКА ДИСКА
# #------------------------------------------------------------------------------
# Полная очистка диска от старых разделов и подписей.
wipefs --all --force /dev/sdx
sgdisk -Z /dev/sdx
# #------------------------------------------------------------------------------
# ШАГ 2: СОЗДАНИЕ РАЗДЕЛОВ
# #------------------------------------------------------------------------------
# Создание новой таблицы разделов GPT с выравниванием 2048 секторов.
sgdisk -a 2048 -o /dev/sdx
# 📦 РАЗДЕЛ 1: EFI System Partition (ESP) — 1024 МБ, тип ef00
# Назначение: systemd-boot, UKI, ядро и initramfs.
sgdisk -n 1::+1024M --typecode=1:ef00 --change-name=1:"EFI System Partition" /dev/sdx
# 📦 РАЗДЕЛ 2: LUKS-контейнер — всё место, тип 8309 (Linux LUKS)
# Назначение: зашифрованный том; Btrfs будет создана ВНУТРИ него (БЛОК 7B).
# ℹ️ Тип раздела — подсказка для утилит, на шифрование он не влияет: работает
#    и 8300 (Linux filesystem), но 8309 честно говорит «здесь LUKS».
sgdisk -n 2::-0 --typecode=2:8309 --change-name=2:"LUKS Root Arch Linux" /dev/sdx
# ⏳ Ждём, пока udev создаст узлы разделов (/dev/sda1, /dev/sda2). Без этой
#    паузы следующий блок иногда начинается раньше, чем узлы появились, и
#    mkfs/mount заканчиваются ошибкой «No such file or directory».
udevadm settle --timeout=15
# #------------------------------------------------------------------------------

# #------------------------------------------------------------------------------

# ℹ️ Зачем: FAT32 на ESP и зашифрованный контейнер LUKS2 на sda2.

# 📌 Схема:
# • sda1 — ESP (FAT32, будет смонтирован в /boot в БЛОКЕ 7C).
# • sda2 — LUKS2-контейнер cryptroot; Btrfs появится ВНУТРИ него (БЛОК 7B).
# 🔐 cryptsetup luksFormat — ИНТЕРАКТИВНАЯ команда: напечатать YES, затем
#    дважды ввести пароль. Поэтому она ПОСЛЕДНЯЯ в блоке: всё, что вставлено

#    → БЛОК 7B (Btrfs и подтома) → БЛОК 7C (монтирование).
# ⌨️ Раскладка — латинская (us): команда loadkeys us ниже переключает live-среду
#    с русской раскладки БЛОКА 2. Иначе пароль запишется кириллицей, а при
#    загрузке (раскладка тоже us) ввести его будет невозможно.
# 🔑 Параметры LUKS2 — значения cryptsetup по умолчанию: шифр aes-xts-plain64,
#    ключ 512 бит, PBKDF argon2id. Ничего не указываем сознательно: такой
#    контейнер открывается любым современным cryptsetup, включая live-ISO.
# 💡 Резервный ключ (второй слот) можно добавить позже, в установленной
#    системе: sudo cryptsetup luksAddKey /dev/sda2 — спросит текущий пароль,
#    затем новый. В макете этого шага нет: по умолчанию только пароль.

#    по нему система находит корень после «Восстановить копию» в btrfs-assistant
#    (подтом переименовывается, а имя @ остаётся за восстановленным состоянием).
#    Проверка в конце блока: у строки "/" опции должны содержать subvol=/@.
# 🔐 /etc/crypttab НЕ нужен и не создаётся: корневой контейнер cryptroot
#    открывает initramfs по параметру ядра rd.luks.name=<UUID>=cryptroot
#    (БЛОК 12). crypttab применяют только для НЕкорневых зашифрованных томов —
#    в этом макете их нет. Строки /dev/mapper/cryptroot нет и в fstab: genfstab
#    записал корень по UUID файловой системы, лежащей ВНУТРИ контейнера, —
#    после открытия контейнера этот UUID всегда доступен системе.
# 📋 Закрываем ESP от остальных пользователей. FAT не хранит права Unix — их
#    задают маски монтирования, а systemd-boot держит на ESP loader/random-seed.
#    Без этого bootctl пишет: "Mount point '/boot' which backs the random seed
#    file is world accessible, which is a security hole!". Прошивке маски не
#    мешают: она читает FAT напрямую, минуя права доступа.
# ⚠️ Побочный эффект: после этого обычный пользователь НЕ СМОЖЕТ читать /boot —
#    команды вроде ls /boot, cat /boot/loader/loader.conf, bootctl, sbctl нужно
#    выполнять через sudo. Это ожидаемое поведение, а не поломка.
sed -i '\|[[:space:]]/boot[[:space:]]|{s|fmask=[0-9]*|fmask=0177|; s|dmask=[0-9]*|dmask=0077|}' /etc/fstab

# ℹ️ Зачем: Установка ядра linux-lts, сборка UKI, установка systemd-boot.
# 💡 Загрузчик — systemd-boot, а НЕ GRUB: при включённом Secure Boot GRUB из
#    Arch отказывается грузить свои модули без shim (ошибка shim_lock_verifier).
# ❗ КРИТИЧЕСКИ ВАЖНО: без корректных настроек система НЕ ЗАГРУЗИТСЯ!
# 📌 ESP монтируется в /boot.

# ШАГ 1: ЯДРО, ПРОШИВКИ, СЕТЬ, SSH, PLYMOUTH
# #------------------------------------------------------------------------------
# 📦 linux-lts — ядро с долгосрочной поддержкой (~100 МБ)
# 📦 linux-lts-headers — заголовки ядра для сборки внешних модулей (DKMS) (~15 МБ)
# 📦 linux-firmware — прошивки для оборудования (~200 МБ)
pacman -S --noconfirm linux-lts linux-lts-headers linux-firmware
# 📦 networkmanager — управление сетевыми подключениями (~2 МБ)
# 📦 wpa_supplicant — поддержка WPA/WPA2 для WiFi (~0.8 МБ)
pacman -S --noconfirm networkmanager wpa_supplicant
# 📦 openssh — сервер и клиент SSH для удалённого доступа (~2 МБ)
pacman -S --noconfirm openssh
# 📦 plymouth — экран загрузки с анимацией (~3 МБ)
pacman -S --noconfirm plymouth
# 🔧 Включение системных служб (btrfs-снимки в меню — БЛОК 13A, не grub-btrfs).
systemctl enable NetworkManager.service sshd.service
# #------------------------------------------------------------------------------
# ШАГ 2: ИНСТРУМЕНТЫ ДЛЯ UKI И SECURE BOOT
# #------------------------------------------------------------------------------
# 📦 systemd-ukify — сборка UKI (единый образ ядра)
# 📦 sbctl — ключи и подпись файлов для Secure Boot
pacman -S --noconfirm systemd-ukify sbctl
# 📁 Каталоги: без них ukify/mkinitcpio могут завершиться ошибкой
mkdir -p /etc/kernel /boot/EFI/Linux
# 📋 Параметры ядра — ЕДИНСТВЕННОЕ место, где они задаются (файл /etc/default/grub
#    больше не используется). Тихая загрузка (quiet splash loglevel=3, аналог
#    прежнего GRUB_CMDLINE_LINUX_DEFAULT) добавляется сюда позже, в БЛОКЕ 20.
# 🔐 ПАРАМЕТРЫ ШИФРОВАНИЯ — без них система не загрузится:
#    rd.luks.name=<UUID контейнера>=cryptroot — initramfs откроет зашифрованный
#      раздел и назовёт устройство cryptroot. Без «=cryptroot» имя было бы
#      luks-<UUID>, и root= перестал бы совпадать;
#    rd.luks.options=discard — пропускать TRIM через dm-crypt (нужно для SSD;
#      ценой раскрытия сведений о занятом месте. Не нужно — удалите параметр);
#    root=/dev/mapper/cryptroot — корень на РАСШИФРОВАННОМ устройстве, а не
#      на разделе sda2.
# ❗ rootflags=subvol=@ ОБЯЗАТЕЛЕН: корень монтируется явно по ИМЕНИ подтома.
#    Эта схема совместима с «Восстановить копию» в btrfs-assistant (подтома
#    переименовываются, а имя @ остаётся за восстановленным состоянием) и с
#    записями-снимками в меню загрузки (БЛОК 13A). Схема с подтомом по
#    умолчанию (snapper rollback) с ними конфликтует — см. комментарий в БЛОКЕ 7C.
# ❗ quiet splash loglevel=3 намеренно НЕ включаем. Пока система ни разу успешно
#    не загрузилась, подробный лог — единственный способ увидеть причину сбоя.
#    Тихая загрузка включается в БЛОКЕ 20, после первой успешной загрузки.
# 📋 UUID контейнера берём из его заголовка (тот же UUID показывал lsblk в БЛОКЕ 7B).
LUKS_UUID="$(cryptsetup luksUUID /dev/sda2)"
# 🔍 Защита от пустой строки: без UUID initramfs не найдёт контейнер.
[ -n "$LUKS_UUID" ] || echo "❗ UUID контейнера не получен: проверьте имя раздела (sda2 заменён на ваш?) — cryptsetup luksUUID /dev/sda2"
echo "rd.luks.name=${LUKS_UUID}=cryptroot rd.luks.options=discard root=/dev/mapper/cryptroot rw rootflags=subvol=@" > /etc/kernel/cmdline
# #------------------------------------------------------------------------------
# ШАГ 3: НАСТРОЙКА MKINITCPIO (HOOKS И MODULES)
# #------------------------------------------------------------------------------
# ℹ️ Используются systemd-хуки (нужны для plymouth, шифрования и снимков):
#    base — остаётся первым, как в ArchWiki;  systemd — заменяет udev;
#    microcode — ОБЯЗАТЕЛЕН: с UKI микрокод упаковывается внутрь initramfs;
#    keyboard — драйверы клавиатуры в ранней загрузке: без них пароль LUKS
#      будет некому ввести (на ПК с внешней/USB-клавиатурой хук полезно ставить
#      ещё и ДО autodetect — здесь оставлен порядок из ArchWiki);
#    sd-vconsole — раскладка и шрифт консоли, в том числе для запроса пароля;
#      ОБЯЗАТЕЛЬНО ДО sd-encrypt: к запросу пароля применяется KEYMAP из
#      /etc/vconsole.conf (у нас us — см. БЛОК 9);
#    plymouth — ДО block и sd-encrypt, чтобы заставка появилась раньше запроса
#      пароля (иначе пароль пришлось бы вводить на чёрном экране);
#    sd-encrypt — systemd-вариант хука encrypt: открывает cryptroot по
#      rd.luks.name=… из параметров ядра. Именно sd-encrypt, НЕ encrypt:
#      только он работает с plymouth и с systemd-генераторами;
#    lvm2 НЕ добавляем — LVM в этом макете не используется (решение владельца).
sed -i "s|^HOOKS=(.*)|HOOKS=(base systemd autodetect microcode modconf kms keyboard sd-vconsole plymouth block sd-encrypt filesystems fsck)|" /etc/mkinitcpio.conf
# 📋 Явно добавляем модули btrfs и dm-crypt — надёжнее, чем полагаться на
#    autodetect (в VirtualBox autodetect иногда не добирает dm_*).
sed -i "s/^MODULES=()/MODULES=(btrfs dm_mod dm_crypt)/" /etc/mkinitcpio.conf
# #------------------------------------------------------------------------------
# ШАГ 4: НАСТРОЙКА ПРЕСЕТА НА СБОРКУ UKI
# #------------------------------------------------------------------------------
sed -i "s|^PRESETS=.*|PRESETS=('default')|" /etc/mkinitcpio.d/linux-lts.preset
sed -i 's|^default_image=|#default_image=|' /etc/mkinitcpio.d/linux-lts.preset
sed -i 's|^#\?default_uki=.*|default_uki="/boot/EFI/Linux/arch-linux-lts.efi"|' /etc/mkinitcpio.d/linux-lts.preset
sed -i 's|^#\?default_options=.*|default_options="--cmdline /etc/kernel/cmdline"|' /etc/mkinitcpio.d/linux-lts.preset
# ℹ️ Строка #default_image останется закомментированной — так и должно быть:
#    отдельный initramfs не собирается, всё упаковывается в UKI.
#    (В БЛОКЕ 13A мы вернём default_image обратно — он нужен записям-снимкам.)
# #------------------------------------------------------------------------------
# ШАГ 5: PLYMOUTH — ТЕМА ЗАСТАВКИ
# #------------------------------------------------------------------------------
# 🎨 bgrt — родная тема Arch (вариация spinner, удерживает логотип прошивки через
#    таблицу BGRT). В VirtualBox BGRT нет, поэтому будет только анимация — это норма.
mkdir -p /etc/plymouth
printf '[Daemon]\nTheme=bgrt\nShowDelay=0\n' > /etc/plymouth/plymouthd.conf

# 🌿  [CHROOT] БЛОК 13A: СНИМКИ BTRFS В МЕНЮ systemd-boot
#################################################################
# ℹ️ Зачем: Полная замена связки grub-btrfs + grub-btrfsd + inotify-tools.
#    Снимки snapper появляются в меню загрузки как отдельные пункты.
# ⚠️ ПОЧЕМУ НЕ UKI: при включённом Secure Boot systemd-stub берёт параметры
#    ТОЛЬКО из секции .cmdline внутри UKI и игнорирует options из записи меню.
#    Подставить rootflags=subvol=@/.snapshots/N/snapshot в подписанный образ
#    нельзя, поэтому снимки грузятся обычной записью Type #1 (ядро + initramfs
#    отдельно). Ядро — PE-образ, прошивка проверяет его подпись, Secure Boot работает.
# 🔐 LUKS: снимки в меню работают и с шифрованным корнем. Запись Type #1 несёт
#    ПОЛНУЮ строку параметров в поле options — вместе с rd.luks.name=<UUID>=
#    cryptroot, поэтому initramfs открывает контейнер (спросит пароль) и
#    монтирует снимок как корень. Ограничение Secure Boot касается только
#    встроенной .cmdline у UKI, а здесь параметры свои — их подстановка возможна.
#    💡 Расплата та же, что и в v4.4: строка options у записей-снимков не
#    подписана. Безопасности это не ломает: без пароля LUKS диск не открыть.
# 📌 Требование: ESP смонтирован в /boot (у нас так), чтобы systemd-boot мог
#    прочитать ядро и initramfs.
# ❗ Порядок: выполнять ПОСЛЕ БЛОКА 12 (нужны systemd-boot и пресет UKI).
#################################################################
# 🧹 Очистка экрана терминала
clear
# #------------------------------------------------------------------------------
# ШАГ 1: ВЕРНУТЬ СБОРКУ ОБЫЧНОГО INITRAMFS (нужен для записей-снимков)
# #------------------------------------------------------------------------------
# ℹ️ В БЛОКЕ 12 мы закомментировали default_image — всё упаковывалось в UKI.
#    Записям-снимкам нужен отдельный initramfs рядом с ядром на ESP.
sed -i 's|^#default_image=|default_image=|' /etc/mkinitcpio.d/linux-lts.preset
# #------------------------------------------------------------------------------
# ШАГ 2: ГЕНЕРАТОР ПУНКТОВ МЕНЮ
# #------------------------------------------------------------------------------
# ℹ️ Единственное исключение в макете: цикл по снимкам должен где-то храниться,
#    чтобы его могли вызывать хук pacman, path-юнит и таймер. Это НЕ скрипт
#    установки — установочные шаги по-прежнему выполняются командами.
# 💡 Что делает: берёт РЕАЛЬНЫЙ список подтомов (btrfs subvolume list /), отбирает
#    те, что похожи на снимки, и создаёт по одной записи меню на снимок.
#    Путь к снимкам не угадывается — поэтому работают и snapper, и btrfs-assistant,
#    и timeshift-подобные схемы. Шаблон отбора можно задать переменной PATTERN.
cat > /usr/local/bin/snapshot-entries <<'EOF'
#!/usr/bin/env bash
# Пункты меню systemd-boot для снимков btrfs (замена grub-btrfs).
# Список снимков берётся из РЕАЛЬНОГО списка подтомов, поэтому не важно,
# чем они созданы: snapper, btrfs-assistant или timeshift.
set -euo pipefail

command -v btrfs >/dev/null 2>&1 || exit 0           # не btrfs — тихо выходим

ESP="${ESP:-/boot}"                                  # для ESP в /boot/efi: ESP=/boot/efi
KERNEL="${KERNEL:-/vmlinuz-linux-lts}"               # пути ОТНОСИТЕЛЬНО ESP
INITRD="${INITRD:-/initramfs-linux-lts.img}"
ENTRIES="$ESP/loader/entries"

# Базовые параметры ядра берём из /etc/kernel/cmdline — тогда записи-снимков
# всегда совпадают с основной записью (quiet/splash включаются и выключаются
# вместе с ней), а rd.luks.name=… переносится в них АВТОМАТИЧЕСКИ: без него
# initramfs не открыл бы контейнер и не дошёл до монтирования снимка.
# Свой rootflags= из базовой строки вычищаем — он будет своим.
BASE="$(sed 's/rootflags=[^ ]*//g; s/  */ /g; s/^ *//; s/ *$//' /etc/kernel/cmdline 2>/dev/null || true)"
# 🔐 Запасная строка (если /etc/kernel/cmdline не читается) тоже обязана
#    открывать LUKS, поэтому имя и UUID контейнера определяем по факту:
#    / → /dev/mapper/cryptroot → раздел sda2 → его crypto_LUKS UUID.
CRYPT_SRC="$(findmnt -no SOURCE /)"                        # /dev/mapper/cryptroot
CRYPT_NAME="${CRYPT_SRC#/dev/mapper/}"                     # cryptroot
CRYPT_PART="$(lsblk -no PKNAME "$CRYPT_SRC" 2>/dev/null | tail -1 || true)"
CRYPT_UUID="$(lsblk -no UUID "/dev/$CRYPT_PART" 2>/dev/null | tail -1 || true)"
[ -n "$BASE" ] || BASE="rd.luks.name=${CRYPT_UUID}=${CRYPT_NAME} root=${CRYPT_SRC} rw"

# Подтом, из которого смонтирован ТЕКУЩИЙ КОРЕНЬ (например "@").
ROOT_SUB="$(findmnt -no SOURCE / | sed -n 's|.*\[\(.*\)\]|\1|p' | sed 's|^/||')"
[ -n "$ROOT_SUB" ] || ROOT_SUB="@"

# 🛑 КОГДА МЕНЮ ТРОГАТЬ НЕЛЬЗЯ (защита от удаления пунктов):
# 1) Загрузка ВНУТРИ снимка (откат через меню загрузки). В снимке каталог
#    .snapshots — пустая директория: без этого выхода генератор удалил бы
#    все пункты меню прямо во время такого сеанса (через 2 мин — таймер).
case "$ROOT_SUB" in
    */.snapshots/*/snapshot)       exit 0 ;;
    */timeshift-btrfs/snapshots/*) exit 0 ;;
esac
# 2) В текущем корне ВООБЩЕ нет каталога снимков. Так бывает в момент
#    «Восстановить копию» в btrfs-assistant: корень уже переименован в
#    @_backup_<время>, а дерево .snapshots переехало в новый корень.
#    Существующие пункты меню остаются верными — не удаляем их.
[ -d /.snapshots ] || [ -d /timeshift-btrfs ] || exit 0

# ❗ Отбираем только снимки КОРНЕВОГО подтома. Снимок другого подтома
#    (например @home/.snapshots/1/snapshot) грузить как корень НЕЛЬЗЯ.
#      snapper   → @/.snapshots/1/snapshot
#      timeshift → @/timeshift-btrfs/snapshots/2026-10-06_21-00-00/@
PATTERN="${PATTERN:-^${ROOT_SUB}/(\.snapshots/[0-9]+/snapshot|timeshift-btrfs/snapshots/[^/]+/[^/]+)$}"

mkdir -p "$ENTRIES"
find "$ENTRIES" -maxdepth 1 -name 'snapshot-*.conf' -delete

# ℹ️ ВАЖНО: "btrfs subvolume list /" печатает пути ПО-РАЗНОМУ в зависимости от
#    подтома по умолчанию — либо от корня ФС ("@/.snapshots/1/snapshot"),
#    либо от самого подтома (".snapshots/1/snapshot"). Поэтому каждый путь
#    приводим к виду от корня ФС: именно такой принимает параметр subvol=.
btrfs subvolume list / | sed 's/^.* path //' | sort -V | while read -r sub; do
    [ -n "$sub" ] || continue
    case "$sub" in
        "$ROOT_SUB"/*) ;;                        # уже от корня ФС
        *)             sub="$ROOT_SUB/$sub" ;;   # был от корневого подтома
    esac
    printf '%s\n' "$sub" | grep -qE "$PATTERN" || continue

    # номер снимка (snapper) либо контрольная сумма пути (другие схемы)
    num="$(printf '%s' "$sub" | grep -oE '/[0-9]+/' | tr -d '/' | head -1 || true)"
    [ -n "$num" ] || num="$(printf '%s' "$sub" | cksum | cut -d' ' -f1)"
    # путь в смонтированной системе — чтобы взять дату создания снимка
    mnt="/${sub#"$ROOT_SUB"/}"
    when="$(date -r "$mnt" '+%Y-%m-%d %H:%M' 2>/dev/null || echo 'дата неизвестна')"
    cat > "$ENTRIES/snapshot-$num.conf" <<ENTRY
title   Arch Linux — снимок $sub ($when)
linux   $KERNEL
initrd  $INITRD
options $BASE rootflags=subvol=$sub
ENTRY
done
EOF
chmod +x /usr/local/bin/snapshot-entries

# #------------------------------------------------------------------------------

mkinitcpio -P

/usr/local/bin/snapshot-entries

[Action]

# ШАГ 5: МГНОВЕННАЯ РЕАКЦИЯ НА НОВЫЕ СНИМКИ (замена inotify из grub-btrfsd)
# #------------------------------------------------------------------------------
# ℹ️ path-юнит systemd сам следит за каталогом /.snapshots и сразу запускает
#    генератор: пункт меню появляется БЕЗ ожидания и без перезагрузки.
#    Пакет inotify-tools НЕ нужен — слежение встроено в systemd.
# 📌 ConditionPathIsDirectory нужен, чтобы юнит не считался упавшим, пока конфиг
#    snapper не создан и каталога /.snapshots ещё нет. После настройки snapper
#    в btrfs-assistant выполните один раз: sudo systemctl restart snapshot-entries.path
# 📌 sleep 2 в сервисе — защита от гонки: snapper сначала создаёт каталог
#    /.snapshots/N, и только потом внутри него подтом snapshot.
cat > /etc/systemd/system/snapshot-entries.service <<'EOF'
[Unit]
Description=Обновить пункты меню systemd-boot для снимков btrfs

[Service]
Type=oneshot
ExecStartPre=/usr/bin/sleep 2
ExecStart=/usr/local/bin/snapshot-entries
EOF
cat > /etc/systemd/system/snapshot-entries.path <<'EOF'
[Unit]
Description=Слежение за снимками btrfs и обновление меню systemd-boot
ConditionPathIsDirectory=/.snapshots

[Path]
PathChanged=/.snapshots
Unit=snapshot-entries.service

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now snapshot-entries.path

# ШАГ 6: ТАЙМЕР — СТРАХОВКА (на случай, если path-юнит не сработал)

[Install]

# • МГНОВЕННО — path-юнит snapshot-entries.path следит за /.snapshots и запускает
#   генератор сразу после создания снимка (в btrfs-assistant, snapper, snap-pac).
#   Перезагрузка не нужна: пункт появится в меню при следующем включении.
# • после любой транзакции pacman — хук zz-snapshot-entries.hook;
# • раз в час и через 2 мин после загрузки — таймер snapshot-entries.timer (страховка);
# • вручную: sudo snapshot-entries
# ⚠️ ЕСЛИ КОНФИГ SNAPPER СОЗДАН ПОСЛЕ УСТАНОВКИ: каталога /.snapshots на момент
#    установки ещё не было, поэтому один раз выполните
#    sudo systemctl restart snapshot-entries.path — дальше всё работает мгновенно.
# 🔍 Если пунктов всё равно нет — диагностика по шагам:
#    ls -d /.snapshots/*/         # существуют ли каталоги снимков вообще
#    sudo snapshot-entries        # скрипт с set -e покажет ошибку сразу
#    ls -1 /boot/loader/entries/  # создались ли файлы snapshot-N.conf
#    bootctl list                 # что реально видит systemd-boot
#    systemctl list-timers snapshot-entries.timer   # работает ли таймер
#
# 📌 Как этим пользоваться после установки:
# • Перезагрузка → в меню появятся пункты «Arch Linux — снимок N (дата)».
#   Если не успеваете выбрать за 3 секунды: sudo bootctl set-timeout 10
# • Откат основной системы: в btrfs-assistant выбрать снимок → «Восстановить
#   копию» → перезагрузка. Пункты меню при этом НЕ удаляются (защита в
#   генераторе). После перезагрузки проверьте: ls /.snapshots/ — если каталог
#   пуст, выполните ОДИН РАЗ БЛОК 13B: он вернёт дерево снимков в новый корень
#   (и пункты меню вместе с ним). Аварийный вариант — загрузиться в
#   пункт-снимок из меню и посмотреть состояние; меню при такой загрузке
#   тоже сохраняется. Команда snapper rollback в этой схеме НЕ
#   используется: она меняет подтом по умолчанию и конфликтует с
#   переименованием подтомов, которое выполняет btrfs-assistant.
# • Изменения внутри загруженного снимка НЕ попадают в основную систему.
# 🔐 При выборе пункта-снимка initramfs спросит пароль LUKS — как при обычной
#    загрузке. Если не успеть ввести его примерно за 90 секунд, systemd прервёт
#    job systemd-cryptsetup@cryptroot и уйдёт в emergency mode. Это не поломка:
#    перезагрузитесь и введите пароль (аварийный сценарий — БЛОК 19).
#
# 🔍 Как убедиться, что загрузились ИМЕННО В СНИМОК (выполнять уже внутри него):
#    cat /proc/cmdline                        → rootflags=subvol=@/.snapshots/N/snapshot
#    findmnt -o SOURCE,TARGET,OPTIONS /       → /dev/mapper/cryptroot[/@/.snapshots/N/snapshot]
#    В основной системе там будет просто subvol=@ — это нормальный вывод,
#    а не признак поломки.
#
# ⚠️ ВАЖНО: /boot (ESP) у снимка и основной системы ОБЩИЙ. Находясь внутри снимка,
#    не обновляйте ядро и не запускайте mkinitcpio -P — файлы arch-linux-lts.efi
#    и initramfs-linux-lts.img перезапишутся сразу для всех пунктов меню.
#    Снимок нужен для осмотра и отката, а не для повседневной работы.
# 📌 Secure Boot: подписывать нужно только ядро (БЛОК 17 его подписывает).
#    initramfs — не PE-образ, подпись не требуется. Сами .conf-файлы не
#    подписываются: при editor no править их из меню нельзя, но физический
#    доступ к ESP позволяет — это общее свойство записей Type #1.
#################################################################

#    ls /.snapshots/ пуст — из меню загрузки пропали пункты снимков, а
#    snapper/btrfs-assistant не видят старую историю. Если в /.snapshots есть
#    нумерованные каталоги — всё в порядке, выполнять блок НЕ нужно.
# 📌 Почему так бывает: откат переименовывает корень (@ → @_backup_<время>)
#    и создаёт новый @ из снимка. Дерево .snapshots (вся история) живёт внутри @
#    и должно переехать в новый корень; иногда перенос не выполняется
#    (окно «Restore was successful but the migration of the nested subvolumes
#    failed»). Тогда история остаётся в @_backup_<время>, а в новом корне —
#    лишь пустой каталог .snapshots. Снимки НЕ удалены — блок переносит
#    дерево обратно, и пункты меню возвращаются.
# 📌 Выполнять из загруженной восстановленной системы от своего пользователя,
#    ОДИН раз после каждого отката через btrfs-assistant (блок сам проверит,
#    нужен ли ремонт).
# 🔐 Команды работают с /dev/mapper/cryptroot — ОТКРЫТЫМ LUKS-контейнером (он
#    уже открыт: блок выполняется из работающей системы). Если вы дали
#    контейнеру другое имя (БЛОК 6) — замените его в командах ниже.
#################################################################

CN=$'\e[0m'; CB=$'\e[1;36m'; CW=$'\e[1;37m'; CG=$'\e[1;32m'; CY=$'\e[1;33m'; CR=$'\e[1;31m'; TB=$'\e[1;30;38;2;0;0;0;46m'; TG=$'\e[1;30;38;2;0;0;0;42m'; TY=$'\e[1;30;38;2;0;0;0;43m'
echo " "
echo "${CB}╔══════════════════════════════════════════════════════════════════════════╗${CN}"
echo "${CB}║${TB} БЛОК 13B: ПРОВЕРКА ДЕРЕВА СНИМКОВ ПОСЛЕ ОТКАТА                           ${CN}${CB}║${CN}"
echo "${CB}╟──────────────────────────────────────────────────────────────────────────╢${CN}"
echo "${CB}║${CW}  Блок сам определит, нужен ли ремонт: если снимки на месте —             ${CN}${CB}║${CN}"
echo "${CB}║${CW}  выведет «чинить нечего»; иначе найдёт backup-копию и вернёт             ${CN}${CB}║${CN}"
echo "${CB}║${CW}  дерево снимков в новый корень.                                          ${CN}${CB}║${CN}"
echo "${CB}╚══════════════════════════════════════════════════════════════════════════╝${CN}"
echo " "
# 🔍 Проверяем, где дерево снимков, и при необходимости переносим его в корень.
if ls -d /.snapshots/*/ >/dev/null 2>&1; then
  echo " ${CG}✅ Дерево снимков уже в корне — чинить нечего.${CN}"
else
  # 📦 Монтируем верхний уровень ФС: в /mnt видны ВСЕ подтома.
  sudo mount -o subvolid=5 /dev/mapper/cryptroot /mnt
  if ls -d /mnt/@/.snapshots/*/ >/dev/null 2>&1; then
    echo " ${CG}✅ Дерево уже в новом корне @ — станет видно после перезагрузки.${CN}"
  else
    # 🔍 Ищем backup, в котором осталось дерево с нумерованными снимками.
    BK=""
    for d in /mnt/@_backup_*/; do ls -d "$d".snapshots/[0-9]*/ >/dev/null 2>&1 && BK="$d"; done
    if [ -n "$BK" ]; then
      echo " ${CY}🔍 Найден backup с деревом снимков: $BK${CN}"
      # 📦 Освобождаем место в новом корне: пустой каталог удаляется; если там
      #    уже успели создать новые снимки — он будет ПЕРЕИМЕНОВАН, а не удалён.
      sudo rmdir /mnt/@/.snapshots 2>/dev/null \
        || sudo mv /mnt/@/.snapshots "/mnt/@/.snapshots-new-$(date +%Y-%m-%d_%H%M%S)" 2>/dev/null
      # 📦 Переносим дерево снимков из backup в новый корень.
      sudo mv "${BK}.snapshots" /mnt/@/.snapshots
      echo " ${CG}✅ Дерево снимков возвращено в корень.${CN}"
    else
      echo " ${CR}❗ Backup с деревом снимков не найден. Выполните и покажите вывод:${CN}"
      echo "    ls -d /mnt/@* ; sudo btrfs subvolume list /mnt | head -30"
    fi
  fi
  sudo umount /mnt
  # 📋 Заново вооружаем слежение за снимками и сразу пересобираем меню.
  sudo systemctl restart snapshot-entries.path 2>/dev/null
  sudo snapshot-entries
  # 🔍 Проверка: нумерованные снимки и пункты меню на месте.
  ls -d /.snapshots/*/ 2>/dev/null
  sudo ls -1 /boot/loader/entries/
fi
echo "${CG}╔══════════════════════════════════════════════════════════════════════════╗${CN}"
echo "${CG}║${TG} БЛОК 13B ЗАВЕРШЁН — ДЕРЕВО СНИМКОВ ПРОВЕРЕНО                             ${CN}${CG}║${CN}"

# 💡 Рекомендуется для современных ПК и ноутбуков.
# 📦 Включает: Plasma, Dolphin, Konsole, Kate, SDDM.
#------------------------------------------------------------------------------
# 🧹 Очистка экрана терминала
clear
# 📦 Установка KDE Plasma и базовых приложений
pacman -S --noconfirm plasma-desktop breeze breeze-cursors breeze-gtk breeze-plymouth kdecoration kinfocenter libplasma qqc2-breeze-style kdeplasma-addons kwayland kwin kwin-x11 layer-shell-qt plasma-integration plasma-workspace plasma-workspace-wallpapers kde-gtk-config plymouth-kcm sddm-kcm systemsettings bluedevil kpipewire kscreen libkscreen plasma-nm plasma-pa powerdevil ksystemstats kwallet-pam kwrited plasma-login-manager polkit-kde-agent plasma-browser-integration
pacman -S --noconfirm kde-system dolphin-plugins kate konsole gwenview elisa okular ark
# 📦 Кодеки, интеграция, порталы Wayland/XDG и поддержка Wayland для Qt
pacman -S --noconfirm ffmpegthumbs poppler-glib qt6-wayland
# 📦 GVFS для монтирования устройств и сетевых дисков (SMB/NFS/OneDrive/MTP)
# ❗ gvfs-google удалён, используйте gvfs-goa (настраивается в Параметрах)
pacman -S --noconfirm gvfs gvfs-afc gvfs-dnssd gvfs-goa gvfs-gphoto2 gvfs-mtp gvfs-nfs gvfs-onedrive gvfs-smb gvfs-wsdd
# 📦 Дисплейный менеджер SDDM
pacman -S --noconfirm sddm
systemctl enable sddm.service
# 🎨 Тема входа Breeze — без неё SDDM показывает блёклую maldives
mkdir -p /etc/sddm.conf.d
printf '[Theme]\nCurrent=breeze\n' > /etc/sddm.conf.d/10-theme.conf
# 🎨 Тема Plymouth Breeze вместо дефолтной bgrt (-R сразу пересоберёт initramfs)
plymouth-set-default-theme -R breeze
# 🖥️ Экран входа тоже в Wayland: композитор kwin_wayland вместо дефолтного weston.
#    Режим экспериментальный, Numlock в нём не настраивается. Чёрный экран на
#    NVIDIA (Сценарии В/Г) — удалите /etc/sddm.conf.d/10-wayland.conf (откат в X11).
cat > /etc/sddm.conf.d/10-wayland.conf << "EOF"
[General]
DisplayServer=wayland
GreeterEnvironment=QT_WAYLAND_SHELL_INTEGRATION=layer-shell

[Wayland]
CompositorCommand=kwin_wayland --drm --no-lockscreen --no-global-shortcuts --locale1
EOF
# 🎬 Пауза 2 с перед стартом SDDM: анимация Plymouth доигрывает, переход плавный
#    (проверка: systemctl status sddm → строка «Drop-In:»; sleep — под длину анимации)
mkdir -p /etc/systemd/system/sddm.service.d
printf '[Service]\nExecStartPre=/bin/sleep 2\n' > /etc/systemd/system/sddm.service.d/override.conf
# 📋 Обновление конфигурации
mkinitcpio -P
# 🧹 Очистка экрана терминала
clear
# 🎨 Цвета окон и рамок (безопасно задавать повторно в каждом блоке)
CN=$'\e[0m'; CB=$'\e[1;36m'; CW=$'\e[1;37m'; CG=$'\e[1;32m'; CY=$'\e[1;33m'; CR=$'\e[1;31m'; TB=$'\e[1;30;38;2;0;0;0;46m'; TG=$'\e[1;30;38;2;0;0;0;42m'; TY=$'\e[1;30;38;2;0;0;0;43m'
echo " "
echo "${CG}╔══════════════════════════════════════════════════════════════════════════╗${CN}"
echo "${CG}║${TG} БЛОК 16 ЗАВЕРШЁН — KDE PLASMA УСТАНОВЛЕНА                                ${CN}${CG}║${CN}"
echo "${CG}╟──────────────────────────────────────────────────────────────────────────╢${CN}"
echo "${CG}║${CW}  Что сделано: Plasma + приложения, SDDM включён (тема breeze,            ${CN}${CG}║${CN}"
echo "${CG}║${CW}  Wayland-гритер), plymouth-тема breeze, initramfs пересобран.            ${CN}${CG}║${CN}"
echo "${CG}║${CW}  Далее: БЛОК 17 — активация Secure Boot.                                 ${CN}${CG}║${CN}"
echo "${CG}╚══════════════════════════════════════════════════════════════════════════╝${CN}"

sbctl enroll-keys -m

# ШАГ 3: ПОДПИСАТЬ ВСЁ, ЧТО УЧАСТВУЕТ В ЗАГРУЗКЕ

#    VirtualBox грузится именно по запасному пути — подписывать ОБА обязательно.

sbctl sign -s /boot/EFI/BOOT/BOOTX64.EFI
# 📋 UKI — основной пункт меню (ядро + initramfs + параметры в одном файле).
#    🔐 Внутри UKI лежит ПОДПИСАННАЯ строка параметров, включая
#    rd.luks.name=<UUID>=cryptroot: при включённом Secure Boot подменить
#    параметры шифрования (например, подсунуть свой root=) прошивка не даст.
#    Это дополнительная защита поверх самого LUKS.

# 📋 Ядро — нужно записям-снимкам из БЛОКА 13A и как запасной путь загрузки.

#    пароля LUKS контейнер они всё равно не откроют.

#    уже известные ему файлы из базы, НОВЫЕ он не находит. Пакет memtest86+-efi
#    кладёт свой образ на ESP, поэтому без явной подписи sbctl verify будет

echo "${CB}║${CW}  Ожидаются 5 файлов: systemd-bootx64.efi, BOOTX64.EFI,                   ${CN}${CB}║${CN}"

#    (ничего не выполнится), а нужные строки копировать по одной вручную.
# 🔐 Почему блок вернулся именно в шифрованной редакции: с LUKS авария почти
#    всегда означает «initramfs не открыл контейнер» или «подпись/параметры

#################################################################
# 🧭 СЦЕНАРИИ: ЧТО СЛУЧИЛОСЬ?
#    • «Welcome to emergency mode» / «Cannot open /dev/mapper/cryptroot»
#      → initramfs не получил rd.luks.name или UUID контейнера изменился
#        (раздел пересоздавали, контейнер пересобирали).
#    • «Access denied» / «Verification requested, but no verification key»
#      → сбилась подпись UKI: ядро пересобрали без sbctl sign-all.
#    • «No key available with this passphrase»
#      → пароль вводят не в той раскладке (нужна us) или пароль неверный.
#    • Меню systemd-boot пустое или грузится не то
#      → повреждены записи на ESP (loader/entries, EFI/Linux).
#
# ⌨️ ШАГ 1. Загрузиться с установочной флешки Arch и задать раскладку:
#    loadkeys us
#    setfont cyr-sun16
#
# 🔓 ШАГ 2. Открыть контейнер (пароль — тот, что задавали в БЛОКЕ 7):
#    lsblk -f                                # найти раздел с crypto_LUKS
#    cryptsetup open /dev/sda2 cryptroot     # sda2 → ваш раздел
#    cryptsetup status cryptroot             # ожидается: active
#
# 🗂️ ШАГ 3. Смонтировать систему (подтома — как в БЛОКЕ 7C):
#    mount -o subvol=@ /dev/mapper/cryptroot /mnt
#    mount -o subvol=@home /dev/mapper/cryptroot /mnt/home
#    mount -o subvol=@log /dev/mapper/cryptroot /mnt/var/log
#    mount -o subvol=@pkg /dev/mapper/cryptroot /mnt/var/cache/pacman/pkg
#    mount /dev/sda1 /mnt/boot               # ESP (sda1 → ваш раздел)
#    arch-chroot /mnt
#
# 🔧 ШАГ 4. Внутри chroot — по симптому:
#    А) UUID контейнера изменился / потерялся rd.luks.name:
#       cryptsetup luksUUID /dev/sda2        # новый UUID контейнера
#       cat /etc/kernel/cmdline
#       nano /etc/kernel/cmdline             # rd.luks.name=<новый UUID>=cryptroot
#       mkinitcpio -P && sbctl sign-all && sbctl verify
#    Б) Слетела подпись (ядро обновилось, а sign-all не выполнили):
#       sbctl status ; sbctl verify ; sbctl sign-all ; sbctl verify
#    В) Пересобрать всё с нуля (самое надёжное):
#       mkinitcpio -P && bootctl update && sbctl sign-all && sbctl verify
#    Г) Проверить хуки и fstab:
#       grep -E '^(HOOKS|MODULES)=' /etc/mkinitcpio.conf
#       cat /etc/fstab
#    Д) Вернуть подробный лог вместо тихой загрузки (чтобы увидеть причину):
#       sed -i 's/ quiet splash loglevel=3//' /etc/kernel/cmdline
#       mkinitcpio -P && sbctl sign-all && sbctl verify
#
# 🚪 ШАГ 5. Выйти и отмонтировать (порядок — как в БЛОКЕ 18):
#    exit
#    umount -R /mnt
#    cryptsetup close cryptroot
#
# 🌿 АЛЬТЕРНАТИВА БЕЗ CHROOT — ЗАГРУЗКА В СНИМОК:
#    Если система сломана обновлением, а снимки целы: в меню systemd-boot
#    выберите пункт «Arch Linux — снимок @/.snapshots/N/snapshot (дата)».
#    initramfs спросит пароль LUKS и загрузит старое состояние — из него
#    можно достать файлы и понять, что сломалось. /boot у снимка и основной
#    системы ОБЩИЙ: ядро из-под снимка не пересобирайте (см. БЛОК 13A).
#
# 📌 Примечание к ШАГУ 4А: cryptsetup luksUUID /dev/sda2 удобнее выполнить ДО
#    arch-chroot (в live-среде) и записать UUID — внутри chroot раздел тоже
#    виден, но так проще.
#
# ☠️ ЗАБЫЛИ ПАРОЛЬ LUKS?
#    Восстановить данные НЕВОЗМОЖНО: у LUKS нет ни сброса пароля, ни
#    восстановления по почте, ни «мастер-ключа» у разработчиков. Единственный
#    путь — разметка заново (БЛОК 5) и новая установка. Именно поэтому пароль
#    стоило записать в менеджер паролей сразу, ещё в БЛОКЕ 7.
# 💡 Что можно спасти: содержимое ESP (оно не зашифровано) — но там только
#    загрузчик и ядро, личных данных нет.
